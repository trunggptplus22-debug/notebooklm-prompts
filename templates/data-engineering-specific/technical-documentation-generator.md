# Technical Specification and Documentation Generator

## Objective
Produce implementation-grade documentation for an algorithm, data model, software module, or hybrid research engine.

## Inputs
- System / module: [INSERT]
- Code, rules, schemas, or notes: [INSERT]
- Intended readers: [INSERT]
- Documentation type: specification / architecture / API / algorithm / operations

## Required Sections
1. Purpose, scope, and non-goals.
2. Terminology and domain assumptions.
3. Inputs, outputs, schemas, units, and validation.
4. Core mechanism and processing sequence.
5. Formal rules, equations, invariants, and constraints.
6. State transitions, branching, exceptions, and termination.
7. Dependencies and interface contracts.
8. Worked examples and expected outputs.
9. Failure modes, limitations, and unresolved decisions.
10. Test strategy and acceptance criteria.
11. Versioning, provenance, and change log.

Document only behavior supported by supplied code or specifications. Mark proposed behavior as proposed. Never invent APIs, schemas, benchmark results, or undocumented conventions.
